Empty, loading & error states

The current build has three bare CircularProgressIndicators, one styled empty state, one plain-text "No audiobooks found for this search.", and no error state at all — network failures surface as a SnackBar or as a silent debugPrint. This page defines the full set.

1. Empty states

Departure from today. The empty library reads "YOUR LIBRARY IS EMPTY" at 16px/w900 with letterSpacing: 2.0 — shouting at someone who has just installed the app. It also stacks two uppercase buttons and repeats the volunteer banner. Sentence case, one primary action, one secondary.

3. Error states

New — none of this exists today. Failures currently vanish into debugPrint('Error scanning library: $e') or into a SnackBar carrying a raw exception string ("Download failed: $e"). Every error here says what failed, what the user can do, and keeps the technical detail available but secondary.

5. State rules

  • Every asynchronous surface declares all four of loading / empty / error / content. A screen with no declared error state is not finished.
  • Loading containers set aria-busy and carry a visually-hidden role="status" describing what is loading.
  • Skeletons mirror the real layout so nothing jumps when content arrives.
  • Errors are role="alert", name the thing that failed, and always offer at least one action.
  • Raw exception text is never the headline. It lives behind a "Technical detail" disclosure so it can still be pasted into a forum report.
  • Empty states are one sentence of orientation plus at most two actions. No uppercase.
