App header, search & navigation

Maps to app_header.dart and storefront_navigation.dart. The header is one component with a container-query breakpoint at 700px; below it, primary navigation moves to a bottom bar, which is where a phone user's thumb actually is.

1. Desktop header — 1280px

Departure from today. The current header is a single unwrapped Row: it does not respond to width at all and will overflow on a phone. Nav pills are 11px FontWeight.w900 uppercase with letterSpacing: 1.0 ("LIBRARY", "DISCOVER", "NOW PLAYING"). The search field animates from a 36px icon to a 200px box with an 11px hint. The theme switch is a 56×28 custom sliding track with 12px icons and no accessible label. All of that is replaced: 15px sentence-case nav at 44px tall, a persistent search field, and a labelled theme toggle. The wordmark moves to the serif face — it is a library, not a console.

3. Accessibility contract

  • Header is <header> / Semantics(header: true); nav is a labelled landmark. The current build has neither.
  • The theme switch is a labelled toggle with aria-pressed / Semantics(toggled:). The current sliding switch has a tooltip but no semantic role.
  • Search is a real type="search" field with a visible label or an aria-label, and results are announced through a polite live region ("24 books found").
  • Search is never hidden behind an animated icon. Collapsing it costs a tap and hides the app's most important affordance from anyone scanning the screen.
  • Every nav destination is reachable by keyboard in visual order, with the same focus ring as everything else.
